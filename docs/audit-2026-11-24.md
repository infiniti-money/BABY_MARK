Migrations `0001`–`0005` remain the starting schema/catalog/auth/storage/retention foundation. `0006_management.sql` adds address/audit/indexes and schedule/leave guards; `0007_attendance_security.sql` adds challenge state, image hash/source, receipt/stamp timestamps and preserved metadata; `0008_resource_guards.sql` adds fourteen-store/fifty-active-account capacity and in-flight branch-edit guards. The reported attendance time is `server_timestamp=received_at`, the server upload acceptance time. The image displays the earlier `stamp_issued_at` challenge time, within the 90-second validity window. A hash and challenge bind accepted bytes/metadata; neither demonstrates that the rendered text, GPS or physical camera scene is authentic. Original legacy photos default to `LEGACY_UNVERIFIED`, rather than being relabeled trusted.

## Verification recorded so far

**48 unit/real-SQL tests passed locally**. They cover auth/session behavior, permissions, assignment/leave races including concurrent manager-scope revocation, challenge/replay/oversize handling, server timestamps, photo privacy, CSV escaping and corrections, actual SQLite migrations/constraints, KV reservation failure accounting, concurrent locks, oldest-first capacity behavior, calendar retention/holds/rollback and store/account capacity. SQLite tests exercise real SQL but do not by themselves reproduce edge KV consistency or deployed CPU limits.

The active static build and Pages Functions bundle compiled locally with Wrangler **4.167.0**. Node **26** was used locally. The committed workflow targets Node **22**, but no remote CI success is asserted here.

**Seven browser acceptance tests passed** against local workerd/Miniflare with real ephemeral D1/KV, synthetic GPS and fake camera: admin account/store/overnight scheduling; employee IN/OUT and protected JPEG retrieval; scoped report export; transparent-overlay/200KB high-entropy rendering; leave submission/scoped approval preserving originals; credential reset/lock/unlock with revocation; and offline logout clearing local data and stopping camera tracks. The tested server uses the compiled Pages Functions, without mocked business API responses. Explicit desktop/mobile/Timemark screenshots use synthetic fixtures only.

No production request, migration, deployment, retention cleanup, capacity deletion or physical-device test was performed. The source review also does not claim the retired Next/Expo apps were repaired or rebuilt.

## Remaining blockers and operating decisions

- Confirm production resource/binding identity and backups, then rehearse only unapplied migrations on a representative isolated copy. Preflight existing schedule overlaps, missing credentials and more than 50 active non-admin accounts before rollout. New triggers do not repair old records.
- Confirm actual store GPS and addresses; accept physical Android/iOS HTTPS camera/GPS and Vietnamese Timemark legibility, weak-network and session-switch behavior.
- Remote CI must be verified separately; measure production Workers CPU/memory, D1 query/storage and account-wide KV quotas before promising free operation. Native Sharp, browser Canvas and Cloudflare Images are not interchangeable runtime capabilities.
- Review activation of photo eviction and D1 retention separately. Neither deletion flag was enabled. KV expiration alone is not an autonomous D1 cleanup schedule; a scheduled Worker/external caller needs a separate authorized decision if required.
- Document operator reconciliation for interrupted storage locks, `PROCESSING` challenges and uncertain D1/KV outcomes. No automatic lease stealing or blind deletion was introduced.
- Native Expo migration, push/realtime reminders, shift swaps, native XLSX and payroll remain unimplemented in the active target. Retained legacy code is not evidence of Cloudflare feature parity.

See [Cloudflare operations](./cloudflare-operations.md) for configuration, local verification, privacy/trust boundaries and rollout preflight. The verified deliverable is the source upgrade and local evidence; production activation is a separate, unperformed change.
