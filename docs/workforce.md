# v0.4 workforce
Run schema.sql → notifications.sql → workforce.sql → workforce-notifications.sql for fresh database. Existing v0.3 database: backup and run only unapplied scripts in order. Review changes first; no real database has been migrated by the GitHub commit.
Admin creates Auth users manually and then creates staff/manager profile using UUID. Set branch manager membership in web UI. Do not share service-role key.
Managers have read and approval access to assigned branches plus their own assignments; no global employee list, GPS configuration or shift editing. Admin remains responsible for scheduling. A staff profile is visible to a manager when that employee has an assignment in a managed branch (including historical assignment). Verify this scope matches HR policy.
Requests are per shift, not multi-day. Correction provides both proposed times in Vietnam timezone. Only approved changes affect reporting; raw log remains immutable. Leave is excluded from paid-day calculations; paid/unpaid leave balances and payroll are not implemented. One pending or approved request per shift; rejected can be resubmitted. No self-approval. Decision note and actor/time preserved. Existing notifications are not retroactively removed.
Test with one admin, two managers assigned to different branches, two staff: cross-branch reads, storage URL generation, direct write denial, self-approval denial, approval races, blocked leave check-in, correction report and original evidence, disabled account access. Verify role-specific views. Test SQL and build before rollout.
