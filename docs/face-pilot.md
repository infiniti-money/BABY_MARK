# Face verification pilot — integration foundation, not a deployed biometric service

0014 creates only opt-in user flags, short-lived session references and manual decisions; no face image or embedding. Normal attendance remains unchanged. GPS uses existing branch radius and 50m accuracy. Pilot exceptions are recorded as original attendance evidence but excluded from work totals until the scoped manager/Admin approves each exception; no self-approval. Outside-zone policy remains unchanged. No automatic rejection of the worker's wages.

A separately implemented and independently tested trusted verification gateway is REQUIRED; no provider is deployed by this commit. The gateway must offer authenticated POST /enrollment-status, /start and /result using FACE_GATEWAY_TOKEN (server-only, >=32 chars), FACE_GATEWAY_URL (HTTPS origin). Start receives session_id, subject_id (pseudonymous employee UUID), assignment_id, type, expires_at; returns same session_id and same-origin HTTPS url with short-lived access to the interactive camera workflow. Result receives same session/user/assignment/type and returns exact identifiers and true liveness_passed, match_passed, enrollment_verified only when server-side provider verification passes and the subject's supervised 1:1 enrollment is valid. Enrollment status returns subject_id and enrollment_verified. Do not implement this as a client-reported score, mock production gateway or a generic search across employee faces. Revoke provider templates on withdrawal/offboarding and delete sessions promptly; disabling pilot stops enforcement and deletes its local sessions but does not delete external templates.

Candidate AWS Rekognition Face Liveness + CompareFaces (React Amplify UI, trusted backend, minimal audit images, encrypted reference, temporary scoped streaming credentials; no public AWS secret). Requires separate gateway deployment, region and data protection assessment, configuration and real device tests. Reference: https://docs.aws.amazon.com/rekognition/latest/dg/face-liveness-programming-api.html and https://docs.aws.amazon.com/rekognition/latest/dg/face-liveness-requirements.html . Never enable for all employees before pilot, notice, lawful basis, data retention/deletion, cross-border assessment if applicable, accessibility and review procedures. Face and GPS do not guarantee physical presence or camera integrity. Browser-captured Timemark remains separate from provider reference image; not cryptographically bound to its pixels.
