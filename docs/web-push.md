# Web Push BABY MARK (PWA)
1. Apply migration 0009 (if not already), then 0010_web_push.sql once. Existing logins and attendance do not require push tables. No opt-in by default.
2. Create a P-256 VAPID key pair locally: node --input-type=module -e "const k=await crypto.subtle.generateKey({name:'ECDSA',namedCurve:'P-256'},true,['sign','verify']);console.log(JSON.stringify(await crypto.subtle.exportKey('jwk',k.privateKey)))" . Put the resulting private JWK in Cloudflare Pages secret PUSH_VAPID_JWK, never GitHub or chat. Set PUSH_VAPID_SUBJECT to an administrator contact mailto: address. Generate a separate random >=32 character PUSH_CRON_SECRET. Redeploy Pages.
3. Admin > Push điện thoại > enable Push, reminders, late alerts. Also enable in-app late alerts in Quản trị > Cài đặt for late alerts.
4. iOS/iPadOS 16.4+: Safari > Share > Add to Home Screen; open icon, login, Push điện thoại > Bật Push; approve. Android supported browser or PWA. Send test; 2xx means push service accepted, not that device displayed it. Test with app closed and screen locked. 
5. Deploy a separate free Worker from cloudflare/push-scheduler (NOT the old baby-mark Worker): cd cloudflare/push-scheduler; npx wrangler secret put PUSH_CRON_SECRET (same value as Pages); npx wrangler deploy. Cron every 2 minutes calls authenticated Pages endpoint; no public worker URL. Confirm dashboard cron events and monitor quotas.
6. No data payload: standards-based VAPID empty push, generic notification; employee data is available only after opening and signing in. Push delivery best effort; no guaranteed exact time. Max 3 devices/account, max 12 deliveries per dispatch; dedupe per endpoint and event; uncertain delivery not retried, expired endpoints removed. A 15-minute late-alert catch-up and 10-minute reminder window are used; high volume, network errors, quota and OS restrictions may cause delays or omissions. Browser endpoint ownership relies on its secrecy. Logout tries both local unsubscribe and server removal; offline logout cannot prove remote removal. Push test does not confirm delivery; no physical device test performed. No third-party paid push service.

Admin → Quản trị → Vận hành now reports fixed VAPID diagnostic codes without revealing secrets. A bare email is normalized to mailto:. The key pair must pass a local sign/verify check before admin activation. This does not prove APNs/FCM accepted a push or the scheduler ran. Do not rotate a valid existing key unnecessarily; subscriptions may require re-registration if it changes.
