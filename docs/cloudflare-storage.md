# Cloudflare D1 + Workers KV — no R2 (migration pilot)
Target: 50 employees, 14 stores. JPEG maximum 200000 bytes (200 KB); TTL 60 days maximum, capacity eviction oldest first. At 100 photos/day and 200 KB each, 20 MB/day; 60 days would require 1.2 GB, exceeding KV free allowance. Application payload budget 900 MB, approximately 45 days at maximum image size (60 days if average image <=150 KB). The remaining account quota is headroom for key overhead, other namespaces and eventual deletion. This is a target, not a guarantee of zero cost. Monitor account-wide usage; KV also has daily request quotas, including deletes. Keep free plan and do not enable paid usage automatically.
## Setup
1. Create D1 babymark-db and execute cloudflare/d1/0001_initial.sql, 0002_store_catalog.sql, 0003_internal_auth.sql, 0004_photo_retention.sql, 0005_attendance_retention.sql in order, only unapplied scripts. No fabricated GPS.
2. Create KV namespace babymark-timemark. Pages settings → Bindings: D1 DB, KV TIMEMARKS. No R2. Internal D1 accounts: docs/internal-auth.md. No Supabase Auth for Cloudflare path. Root repo; output docs. Redeploy. /api/cloudflare/health checks storage connections only.
3. Photo GET /api/cloudflare/photo/<record-id> requires internal bearer token and scoped access. Returns 410 after expiration or capacity deletion; no public URL. D1 attendance records remain untouched. Inventory tombstones record capacity vs TTL removal and hide eventually consistent old KV values.
4. Trusted helper cloudflare/lib/timemark-kv.mjs validates size and JPEG markers, reserves D1 inventory before KV put, expires images after 60 days, evicts oldest stored image(s) before crossing 900 MB. It is NOT yet wired to the public attendance API. Existing images must be inventoried before using this policy. Do not run with untracked KV writes.
5. If a worker is interrupted and lock is stuck, verify no writer is active before clearing photo_storage_lock.owner/acquired_at in D1. Pending entries count toward budget until TTL; reconcile unknown writes manually. Do not run concurrent bypass writers or automatically steal lock. Retry busy requests with backoff. Deletion is irreversible; disclose rolling retention to employees and confirm legal/business needs before enabling. Tests: node --test cloudflare/tests/*.test.mjs.
## Before production
Implement trusted server stamp/compression, authenticated attendance write API, idempotency and failure reconciliation, quota monitoring and retry UX. Validate image readability at the target size. Confirm retention and privacy policy. Current Next.js/Supabase backend remains legacy; Cloudflare path is not fully integrated. No Cloudflare resources or live data were created by the GitHub update.
Official docs: https://developers.cloudflare.com/kv/platform/pricing/ and https://developers.cloudflare.com/kv/api/write-key-value-pairs/
