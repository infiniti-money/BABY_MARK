# Next release roadmap (proposed v1.2.5; no version bump yet)
Baseline v1.2.4 Stable, 81109a2. First PR adds read-only foundations, no schema migration or production mutation.
## N1 Leave balance
GET /api/leave-usage?year=2026 (self; Admin can pass user_id). Counts approved/pending shifts and distinct dates based on retained assignments. No legal entitlement or remaining balance implied; entitlement and balance are null. Retention can remove historical evidence, so never use this query as a durable ledger. Before implementing balance: choose entitlement by employee/year, unit (hours or days/half days), start-date proration, carryover expiry, leave types, paid/unpaid policy and treatment of existing approvals. Admin explicitly enters grants, append-only ledger with request linkage, atomic idempotent debit/reversal, no default or retroactive deduction. Preserve current payroll until paid leave rules approved. Add UI and tests of concurrent approvals, negative balance, rollover and revocation.
## N2 Future shift swaps
Proposed: own future assigned shift, counterpart accepts, then scoped manager/admin approves (neither participant self-approves). Revalidate active employment, branch scope for both, future time, unchanged assignments, overlapping schedules, no attendance/challenge/request/extra/history. Existing assignment overlap triggers make two simultaneous owner updates unsafe for overlapping shifts: design dedicated transaction with immutable swap audit and a migration tested in SQLite and workerd; do not delete/recreate shifts with evidence. Cancel/reject/expire without schedule mutation. No implementation of writes in this PR.
## N3 Production performance
Run manual workflow BABY MARK public production probe or locally node scripts/production-probe.mjs. 3 anonymous GET samples per public path, median/max HTTP duration, decoded bytes, cache policy and health structure. No private data, auth, mutations or persistent client telemetry. Not LCP/INP/CLS or authenticated D1 latency; use real device DevTools and authorized Cloudflare metrics for those. Targets LCP <=2.5s, INP <=200ms, CLS <=0.1 at p75; no measurements claimed yet.
## N4 Backup
Owner export and encryption per docs/backup-recovery-v12.md; D1 SQL import only into authorized isolated environment. Existing backup-local tool creates/verifies/rehearses SQLite snapshots; node scripts/verify-backup-readiness.mjs BACKUP_DIR adds full integrity, FK/checksum and catalog validation against 0023. No record values printed. KV photos separately inventory and sample hashes/expiry in isolated rehearsal; confirm D1 Time Travel availability, export date, RPO/RTO, encryption and access. No production credentials or data in CI/GitHub/chat. Full production backup/restore not verified by offline test. No automatic retention, migration or remote restore.
## Release gate
Each phase independently verified by CI/Pages; no stable version increment until integration and operator acceptance. No paid plan, payroll formula or leave policy changes without approval.
